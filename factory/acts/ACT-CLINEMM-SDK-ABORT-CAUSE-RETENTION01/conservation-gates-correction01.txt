ACT-CLINEMM-SDK-ABORT-CAUSE-RETENTION01 / CORRECTION01 conservation + correlation
===============================================================================

WHY A CORRECTION WAS NEEDED
---------------------------
The first implementation (`10c1546cd`) keyed the abnormal-terminal retention
scope on a SINGLE run id. The production SDK mints TWO run identities for ONE
run:

  - `AgentRuntime`   `agent-runtime.ts:1767`
        `this.state.runId = createUID("run")`
    -> carried by every MODEL-REQUEST observation.
  - `SessionRuntime` `session-runtime-orchestrator.ts:1151`
        `this.activeRunId = run_${Date.now()}_${...}`
    -> carried by the RUN-TERMINAL observation.

A scope keyed on either one alone silently DROPS the other half of the
evidence. The CORRECTION01 RED witness demonstrated this against the REAL
`SessionRuntime`:

  expected [ 'run_terminated' ] to include 'model_request_error'
  (the snapshot contained the run-terminal record but NO provider-terminal
   record, because the two records carried different run ids)

THE REPAIR
----------
The retention scope is now keyed on the MANDATORY `sessionId`, and admits a
record when it shares the session AND EITHER
  (a) the observed run id, OR
  (b) the observed `modelRequestId`.

The `sessionId` remains a MANDATORY part of the join, so concurrent sessions
still cannot contaminate each other. The two run identities are preserved
as DISTINCT fields on the records — they are never conflated and never
synthesized.

Unifying the two run identities would have required changing the run
result's `runId` — a PRODUCTION SEMANTIC change that is explicitly OUT of
this ACT's conservation scope.

       session A's snapshot, even when a run id or a model request id
       collides.
       -> PASS

  T15  the retained records still carry their OWN run ids
       The snapshot must preserve both distinct run ids rather than
       rewriting one into the other.
       -> PASS

  T16  the run result's `runId` is unchanged
       The SDK run result's run id is byte-for-byte the orchestrator's own
       `activeRunId`; the ACT did not rewrite it.
       -> PASS
