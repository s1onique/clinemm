ACT-CLINEMM-SDK-ABORT-CAUSE-RETENTION01 / C4 terminal-correlation tests
========================================================================

C1 FROZEN EVIDENCE CONTRACT (as implemented)
--------------------------------------------
  model_request_started
         |
         v
  model_request_terminal          (model_request_error | model_request_abort
         |                          | model_request_finish)
         v
  sdk_run_terminal                (run_terminated)
         |
         v
  host_lifecycle_observation      (the EXISTING host lifecycle trace —
                                   sdk-session-event-coordinator.ts
                                   lifecycleTransitionTraceRecord)

  An INDEPENDENT abort-origin event (run_abort_requested) may occur
  before or during the provider request.

  Contract clause honoured: "Do not assume that every request has a
  terminal provider event." A request with no observed terminal provider
  event is reported as `in_flight_at_run_end` — never silently
  classified as `provider_error`.

CORRELATION IDENTITY (only fields actually available at each source)
--------------------------------------------------------------------
  | Field            | Provider request boundary | SDK run-terminal boundary | Host |
  |------------------|---------------------------|---------------------------|------|
  | sessionId        | yes (runtime config)      | yes (runtime config)      | yes  |
  | taskId           | no (not known to the      | yes (conversation id)     | yes  |
  |                  | agent runtime)            |                           |      |
  | runId            | yes (runtime state)       | yes (activeRunId)         | yes  |
  | iteration        | yes (runtime counter)     | no                        | yes  |
  | modelRequestId   | yes (minted per request,  | yes (last known, learned  | n/a  |
  |                  | carried on the trace id)  | through the sink wrapper)|      |
  | providerId       | yes                       | yes                       | yes  |
  | modelId          | yes                       | yes                       | yes  |
  | epoch            | NOT AVAILABLE in the SDK  | not available             | yes  |
  |                  | (no epoch concept exists  |                           |      |
  |                  | in agent-runtime.ts or    |                           |      |
  |                  | the orchestrator)          |                           |      |

  An unavailable identity is OMITTED, never synthesized. The `epoch` is
  deliberately absent from the SDK records because the SDK has no epoch
  concept; it is a HOST-side identity and is reused from the existing
  host lifecycle trace rather than invented at the SDK boundary.

  HOST LIFECYCLE OBSERVATION (reused, NOT duplicated)
  --------------------------------------------------
  The host side ALREADY retains its lifecycle decision through
  `apps/vscode/src/sdk/lifecycle-transition-trace.ts`
  (`LifecycleTransitionTraceRecord`), written from
  `sdk-session-event-coordinator.ts` via `lifecycleTransitionTraceRecord(...)`.
  The record carries:
    - `task_id`  — the host-owned task identity,
    - `turn_seq` — the epoch (`messageTranslatorState.getMinter().epoch`),
    - `transition_id`, `decision_id`, `stage`, `outcome`, `source`.
  That trace is the SDK-terminal -> host-receipt -> host-phase-decision
  link required by C1 §4.5. NO second host-phase writer was added and
  `sdk-session-event-coordinator.ts` was NOT modified by this ACT.

  DISTINCT IDENTITIES PRESERVED (not conflated):
  | Identity                 | Owner                | Carried where |
  |--------------------------|----------------------|---------------|
  | modelRequestId           | agent runtime        | trace identity (this ACT) |
  | AI SDK callId            | provider transport   | provider error logs (ai-sdk.ts), NOT on the trace |
  | provider HTTP request id | provider transport   | provider response headers (response-request-id.ts), NOT on the trace |

REQUIRED CAUSAL-FIDELITY ASSERTIONS
------------------------------------
  For a provider exception:
      provider_request_started
              ↓
      provider_terminal_failure
              ↓
      sdk_run_terminal
    All observed records correlate to the SAME run and the relevant model
    request. ASSERTED by T2.

  For a controlled stop:
      runtime_controlled_stop
              ↓
      sdk_run_terminal
    No provider failure is fabricated if none was observed. ASSERTED by
    T5 (zero model_request_error events).

  For cancellation:
      abort_requested
              ↓
      sdk_run_terminal
    The initiating cancellation is attributable to the correct owner
    (`initiator: "agent_runtime"`, `abortOrigin:
    "explicit_abort_request"`). ASSERTED by T4.

  A MISSING `afterModel` callback must not prevent run-terminal evidence:
  the run-terminal observation is emitted by the orchestrator's
  `buildLegacyResult`, which does not depend on any model hook. (The
  retention module's snapshot is keyed on the run, not on the hook.)

RECOVERED ATTEMPTS vs UNRECOVERED TERMINAL FAILURES
----------------------------------------------------
  The production request identity is SHARED across the AI SDK transport
  retries of one agent request (agent-runtime.ts mints ONE
  `modelRequestId` per issued request, in `streamPreparedRequest`, and
  the request is re-issued with the SAME id on the transient-error retry
  path). A retried model request is therefore NOT counted as multiple
  independent agent requests: the trace carries ONE `model_request_start`
  boundary per issued request, and any recovered attempt produces no
  terminal provider error. An UNRECOVERED terminal failure produces the
  `model_request_error` record.
