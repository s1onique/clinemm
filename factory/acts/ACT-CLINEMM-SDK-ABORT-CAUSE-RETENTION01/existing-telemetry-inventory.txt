KEY FINDINGS
------------
F1. modelRequestId is ALREADY minted per model request
    (agent-runtime.ts:2784 `createUID("model_request", 21)`), placed into the
    request metadata (agent-runtime.ts:2788), and propagated to the provider
    layer (ai-sdk.ts:738 reads metadata.modelRequestId). It is also carried by
    the task-lifecycle telemetry channel (agent-runtime.ts:3336). It is NOT
    carried by the model-behavior trace records, so the provider-terminal
    record cannot be joined to the provider's own request identity.

F2. The provider-terminal record carries `errorClass` only
    (agent-runtime.ts:3269 / :3307 -> classifyProviderError). The concrete
    error NAME and MESSAGE are dropped. Two different provider failures with
    the same coarse class are indistinguishable in the retained evidence.

F3. The SDK run-terminal record carries {finishReason,durationMs,iterations}
    (session-runtime-orchestrator.ts:2020-2024). It has NO error identity, so
    a run that ended `aborted` because of a controlled stop is
    indistinguishable from one ended `aborted` because of an explicit cancel.

F4. There is NO abort-origin event anywhere. `AgentRuntime.abort()`
    (agent-runtime.ts:1100) records a task-lifecycle telemetry event but does
    NOT record who initiated it; the orchestrator calls it from at least four
    distinct initiators (host abort signal :544/:906, loop hard escalation
    :2064, recovery-budget stop :2141). `ControlledStopError` (a distinct
    class, agent-runtime.ts:461) is thrown for controlled stops but the
    distinction is only visible via the run result's error message.

F5. The recorder has NO abnormal-terminal retention. Every record is
    symmetric; the operator must dump the whole ring and reconstruct the
    chronology by hand. There is no per-run snapshot that binds the
    provider-terminal record, the run-terminal record and the host receipt.

F6. The host side ALREADY retains its lifecycle decision
    (sdk-session-event-coordinator.ts lifecycleTransitionTraceRecord with
    taskId/epoch). Per C1 §4.5 this must be REUSED, not duplicated.
