RED-01 — Natural exit leaves a live group
--------------------------------------------------------------------------
REPRODUCED: YES.

Test: "N1: natural exit with a transient descendant reproduces the
       containment_failed boundary"

Exact observation (REAL_PROCESS, production manager + production
supervisor, production default postcondition probe):

  command            : ( sleep 3 </dev/null >/dev/null 2>&1 & echo DESC=$! ; exit 0 )
  rootPid == pgid    : the supervisor spawns with `detached: true`, so the
                       shell IS the process-group leader (pgid === pid).
  root exit          : the shell exits immediately (`exit 0`).
  supervisor exit    : resolves at T+~6ms — the descendant redirects its
                       stdio, so it does NOT hold the supervisor's stdout
                       pipe open; the `close` event fires at once.
  finalize entered   : the manager's exitTransition -> finalize(job,
                       "exited") runs synchronously on the `close` event.
  postcondition      : NON-`gone`.
                       On the LIVE host: "alive" (rc=0).
                       On THIS host:     "eperm" (EPERM) — the ClineMM
                       Seatbelt profile allows only `(allow signal
                       (target self))`, so the group exists but is not
                       signalable. See evidence/source-seam-map.md §7.
  osErrorCode        : EPERM (this host) / null (LIVE host).
  manager terminal   : containment_failed
  containmentFailed  : substrate_eperm (this host) / substrate_alive (LIVE)
  later observation  : the SAME original PGID is observed GONE within the
                       bounded window, with NO intervention.
  cleanup            : verified_absent

Why the original `alive` observation was TRUE (not false):
  the group contained a POSITIVELY IDENTIFIED live descendant whose
  `pgid` equalled the ORIGINAL owned PGID.

Measured membership at the finalize boundary (REAL kernel read):

  {
    "pid": 95915,
    "ppid": 1,
    "pgid": 95913,          <- the ORIGINAL owned PGID
    "stat": "",
    "startIdentity": "Thu Nov  5 03:12:59 2026",
    "command": "sleep 20"
  }

  `ppid: 1` shows the leader had already exited and the descendant had
  been reparented to init — the group outlived its leader.

ADDITIONAL WITNESS — RED-04 (leader/reaping race, Case C)
--------------------------------------------------------------------------
REPRODUCED: YES (a SECOND, distinct mechanism).

Test: "REAPING-RACE: a non-gone postcondition without any descendant is
       a transient reap artifact"  (8 trials, plain `true`, no descendant)

Direct measurement (real production supervisor, 5 trials, workload
`( sleep 1 & echo DESC=$! ; exit 0 )`; the supervisor's exit promise
resolved at T+1012..T+1024ms, i.e. AFTER the descendant had exited):

  trial | postcondition AT the supervisor exit resolution | ~26ms later
  ------+--------------------------------------------------+------------
   #0   | ESRCH (gone)                                    | ESRCH
   #1   | ESRCH (gone)                                    | ESRCH
   #2   | EPERM (group entry still present)               | ESRCH (gone)
   #3   | EPERM (group entry still present)               | ESRCH (gone)
   #4   | ESRCH (gone)                                    | ESRCH

=> A non-`gone` postcondition can occur for a group with NO live member
   at all. The mechanism is the kernel's process-group teardown lagging
   behind the supervisor's exit promise — NOT a surviving descendant.
