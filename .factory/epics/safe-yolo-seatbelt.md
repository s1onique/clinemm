## Contract / durable conclusions

- **Seatbelt default-ON on Darwin with explicit OFF break-glass.** `ACT-CLINEMM-SEATBELT-DEFAULT-ON01` is the canonical contract (row 16, board row ~L6342). The Darwin sandbox selector resolves to `SeatbeltSandboxBackendExperimental` whenever the OS-level sandbox feature is enabled (selector contract localized to `apps/vscode`; shared SDK helper reverted; D1-D10 matrix + real-kernel probes written). Default posture: **seatbelt-ON**; explicit `off` is a break-glass path, not a default.
- **Workspace write is bounded to the writable root.** The Safe-YOLO workspace-write contract: under `CLINEMM_SAFE_YOLO=allow`, workspace writes are allowed inside the writable root; `$HOME` writes remain DENIED; child processes inherit the same boundary; `$HOME` reads are allowed (broad-read contract; secret-exfiltration is explicitly out-of-scope per the ACT §16 boundary). See the ACT ledger rows for `SAFE-YOLO-SEATBELT-NETWORK-OPEN01` (which carries the production-seam evidence shape: filesystem policy UNCHANGED under the opt-in) and the file-system policy cross-references in `SAFE-YOLO-SEATBELT-YOLO-QUALIFICATION01` (YOLO does NOT widen filesystem authority).
- **Network-open is an explicit, default-OFF opt-in that does NOT change filesystem policy.** `ACT-CLINEMM-SAFE-YOLO-SEATBELT-NETWORK-OPEN01` (board row ~L6333) flips `buildExperimentalReconCapability`'s `network` field from `"deny"` to `"allow"` ONLY when **both** `CLINEMM_EXPERIMENTAL_SANDBOX=seatbelt` AND `CLINEMM_SAFE_YOLO_NETWORK=allow` are set. Default-OFF (unset → unchanged `"deny"`). Profile generator (`seatbelt-profile.ts`) already emitted the correct `(allow network*)` for `network: "allow"`; **zero** changes to the profile generator were required. **Filesystem policy is UNCHANGED** under the opt-in (workspace writes allowed inside the writable root; home writes DENIED; child-process inheritance same; home reads allowed per broad-read contract).
- **Sensitive-read confinement is curated, not blanket.** `ACT-CLINEMM-SAFE-YOLO-SENSITIVE-READ-CONFINEMENT01` (+ CORRECTION01) is the canonical contract: under `CLINEMM_SAFE_YOLO=allow`, an explicit SSH / GnuPG / macOS-keychain deny list is added to the Seatbelt profile (`~/.ssh`, `~/.gnupg`, `~/.config/.../keychains`, etc.). Broad-read is preserved for everything else; the claim boundary is **curated-deny-list under the opt-in**, not blanket denial (corrected per the reviewer P2 — `id_mldsa44_ed25519` is the OpenSSH 9.9+ ML-DSA-44 / Ed25519 hybrid identity filename; the implementation was already correct, the comment was wrong).
- **YOLO does NOT widen filesystem authority beyond the Seatbelt capability.** `ACT-CLINEMM-SAFE-YOLO-SEATBELT-YOLO-QUALIFICATION01` (+ CORRECTION01) is the reviewer-framed QUALIFICATION (not implementation). Eight-phase matrix against the real production seam proved: enabling the session YOLO override does NOT expand filesystem authority beyond the capability already enforced by Seatbelt. Single bounded seam = `apps/vscode/src/sdk/sandbox-policy.ts` `buildExperimentalReconCapability` (read by `command-job-manager.ts:586`); profile generator and backend are **UNCHANGED**. `HALT_YOLO_SANDBOX_COUPLING` does NOT fire — structural grep of production code shows zero references to `hostAuthorization` / `mode` / `override` / `setOverride` inside `buildExperimentalReconCapability`. The only YOLO-influenced capability that can reach the sandbox is `perCommandExecutionCapability`, gated on `host_safe_mktemp_default_temp` matching, which **narrows** filesystem for the canonical Darwin user temp root — it does NOT widen `$HOME`.
