## PRACTICAL METHOD FOR THIS SESSION

We exercise the workflow commands via direct `sandbox-exec`
invocations of the same Apple substrate (`/usr/bin/sandbox-exec`)
that the installed ClineMM extension invokes through
`manager.start()`. Each command is captured in two forms:

  CONTROL: command run in normal shell, no Seatbelt
  TEST:    command run under `/usr/bin/sandbox-exec -p <profile>`

The Seatbelt profiles for TEST are constructed by hand from the
production generator's output (`generateSeatbeltProfile`) for the
real ClineMM capability that the command would receive. This
exercises:

  - The exact Apple Seatbelt kernel op (file-read*, file-write*,
    file-write-create, network*, etc.)
  - The exact canonical paths produced by the production
    canonicalizer
  - The exact sandbox profile grammar

This is the substrate test, not the wire test. For wire
qualification, the install needs to succeed in a session where the
user can run the harness, or where the agent can drive the UI.

We do NOT substitute this for the IDE qualification. We use it to
discover the first kernel-level boundary (file, network, temp,
cache, child) that a real workflow hits. The IDE qualification
follows in a subsequent session.

## PROFILE USED FOR TEST

We mirror the production `seatbelt-profile.ts` output for the
relevant capability. For read-only workflows (R01..R04), we use a
broad read + deny network profile. For write workflows we add the
specific writable / createOnly / tempRoot grants per the production
resolver. The exact profile bytes for each row are in
`profile-*.sb` files.

This is the same profile shape the installed extension emits; the
canonical paths are realpath-resolved before emission.
