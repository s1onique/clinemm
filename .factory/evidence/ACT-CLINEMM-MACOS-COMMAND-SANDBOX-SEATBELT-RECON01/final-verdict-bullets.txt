KEY IMPLEMENTATION FINDINGS (load-bearing):

1. PATH-SEMANTICS GOTCHA: macOS symlinks (/tmp -> /private/tmp) bypass (subpath ...)
   matching when the textual path doesn't match the canonical resolved path.
   ALWAYS use canonical macOS paths (e.g. /private/tmp, not /tmp).

2. require-not SEMANTICS GOTCHA: Multiple (require-not ...) clauses at the same
   filter level behave as OR (deny only where ALL match), NOT as AND.
   For AND semantics (the typical "exclude these roots"), wrap in (require-all ...).

3. DENY-AFTER-ALLOW WORKS: (allow file-read*) (deny file-read* (subpath OUTSIDE))
   correctly denies OUTSIDE. The deny rule fires for OUTSIDE and symlink targets.

4. NETWORK RULE SYNTAX: (remote ip "localhost:*") works, but "127.0.0.1:*" does
   NOT (profile parse error). The literal-IP form is host-dependent.

5. NETWORK covers AF_UNIX: (deny network*) blocks AF_UNIX connect() to system
   sockets; in-process socketpair() still works (no network involved).

6. process-info / ps: even with (allow process-info*) the /bin/ps binary itself
   cannot be exec'd under a deny-default profile (process exec / image
   activation blocked). This is a known Seatbelt limitation.

7. ENV ISOLATION: Seatbelt does NOT sanitize environment variables.
   SSH_AUTH_SOCK, NIX_SSL_CERT_FILE, HOME etc. all pass through to the child.
   A second layer (env scrubbing) is needed for any production sandbox.

8. EXEC INHERITANCE: bash, sh, env, python3, node children all inherit the
   sandbox boundary. Child execve() cannot escape.

9. SYMLINK ESCAPE: with explicit (deny file-read* (subpath OUTSIDE)), a symlink
   at INSIDE/link-out -> ../outside is blocked when reading INSIDE/link-out/secret.
   Seatbelt evaluates the resolved path, and the deny rule fires.
