WIRE HEX INSPECTION
-------------------
For "truncated \u00" the wire bytes are:
  7b 22 76 65 72 73 69 6f 6e 22 3a 31 2c 22 72 65 71 75 65 73 74 5f 69 64 22 3a 22 63 74 6c 2d 5c 75 30 30 22 2c ...

Decoded ASCII: {"version":1,"request_id":"ctl-\u00",...

The wire contains the LITERAL 4-char ASCII sequence "\u00" (where \u
is a backslash followed by the letter u). This is intentionally NOT
JSON-valid (only 2 hex digits). The C parser sees p[1]=='u', reads
p[2]='0', p[3]='0', but p[4] is '"' (the closing quote). The check
`!p[4] || !p[5]` correctly rejects this — there's no 4th hex digit,
so the escape is malformed. parse_string returns NULL, the envelope
parser converts that to BAD_JSON, and the client receives
{ok:false, error:"BAD_JSON"}.

PRE-CORRECTION04 RECONSTRUCTION (red discriminator)
---------------------------------------------------
If we revert parse_string() to the pre-CORRECTION04 form (8-char switch
without \u), all positive tests FAIL:

  FAIL  ctl-\u0001           response=BAD_JSON (pre-C04 can't decode \u0001)
  FAIL  snowman-\u2603       response=BAD_JSON (pre-C04 can't decode \u2603)
  FAIL  rocket-\uD83D\uDE80  response=BAD_JSON (pre-C04 can't decode \uD83D)

The C helper's parser silently narrowed the wire contract to the
short-escape set, which is a subset of what JSON.stringify produces
and what JSON.parse accepts. This was the P0 protocol-conservation
defect identified by the reviewer.

CORRECTION04 GREEN witness is the 4/4 PASS + 6/6 PASS combined with
the source-level invariant (the \uXXXX branch + hex_value + utf8_encode
are present in helper.c).

GREEN RESULT (P0 PROTOCOL-CONSERVATION)
---------------------------------------
PASS. The C helper's parser now decodes:
  - All 8 short escapes (\", \\, \/, \b, \f, \n, \r, \t)
  - \uXXXX for BMP (16-bit) codepoints
  - \uD83D\uDE80 surrogate pairs for supplementary-plane codepoints
  - Raw UTF-8 bytes (always accepted; bytes >= 0x20 are valid)

And rejects with BAD_JSON (fail-closed):
  - Lone high surrogate \uD800–\uDBFF not followed by \uXXXX low surrogate
  - Lone low surrogate \uDC00–\uDFFF
  - Non-hex digits after \u
  - Truncated \uXXXX (fewer than 4 hex digits)

The frozen wire contract in protocol.ts::buildOkResponse is now fully
conserved end-to-end:
  JSON.stringify → C parse_string → semantic UTF-8 → C write_json_string → JSON.parse
  Result: response.request_id === original request_id, regardless of which
  escape form (or raw UTF-8) JSON.stringify produced.
