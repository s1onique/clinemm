  Root cause: The CORRECTION01 evidence used os.tmpdir() for the

              supposed to close. The CORRECTION01 evidence also
              lacked executable identity binding: the policy
              approved `mktemp` even when the executable that
              would actually run was GNU coreutils (e.g. on this
              developer's darwin host, which mktemp resolves to
              /run/current-system/sw/bin/mktemp = coreutils 9.8).
  Lean fix:   Tighten TempAuthorityEvidence to require BOTH:
              (a) executable identity bound to /usr/bin/mktemp via
                  realpath (PATH-resolved at policy time)
              (b) true Darwin per-user temp root from
                  confstr(_CS_DARWIN_USER_TEMP_DIR) (NOT from
                  os.tmpdir() which honors TMPDIR)
              The host adapter must produce both via subprocess:
              (a) `which -a mktemp` then realpathSync
              (b) `/usr/bin/getconf DARWIN_USER_TEMP_DIR` directly
              Linux remains ASK. The bare form's lexical match is
              necessary but no longer sufficient -- the gate now
              requires both executable identity AND intrinsic
              Darwin temp authority.
              If realpath != /usr/bin/mktemp, evidence is undefined
              and the rule falls through to ASK with new source
              host_mktemp_executable_identity_unbound.
