REVIEWER DISPOSITION
  The slash-bypass proof is correct for the function-lookup
  channel. However, BASH_ENV is a SEPARATE channel:

    GNU Bash Reference Manual, Bash Startup Files:
    When Bash is invoked as a non-interactive shell (e.g., via
    bash -c), it looks for BASH_ENV in the environment, and if
    it is defined, expands the value of that variable and uses
    the expanded value as a file to source BEFORE executing the
    supplied command string.

  Therefore:
    policy authorized C = "/usr/bin/mktemp"
    bash executes S + C = "source $BASH_ENV; /usr/bin/mktemp"

  The proven identity IS the final simple command, but the
  shell can execute arbitrary startup code BEFORE it. Slash
  bypass closes function lookup but does NOT close startup-file
  side effects.

  This affects EVERY bash -c invocation -- not just mktemp.
  Live verification on this darwin-arm64 host shows BASH_ENV
  runs before pwd, ls, git --version, echo, and
  /usr/bin/mktemp.
