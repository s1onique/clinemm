REAL KERNEL WRITE-DENY DISCRIMINATOR (the headline)
================================================================

$ cd apps/vscode && bunx vitest run \
    src/sdk/command-job-manager.sandbox-c3-real-kernel.test.ts \
    -t "write-deny"

Tests run:
  describe("C3: real production kernel write-deny discriminator"):

  PASS: sandbox ON: write to a path under the workspace root is
        KERNEL-DENIED, sentinel bytes unchanged           (32ms)
  PASS: counter-test: same write with sandbox OFF succeeds,
        sentinel bytes change                             (4ms)
  PASS: write to a path outside the workspace AND outside
        /dev/null - kernel still DENIES (deny default +
        empty writableRoots)                             (11ms)

Production-seam proof (verbatim dbg run):

  $ bun /tmp/dbg-test.mjs
  ws= /var/folders/.../dbg-eSzOp0
  state: exited
  exitCode: 1
  signal: undefined
  stdout: ""
  stderr: "/bin/sh: /var/folders/.../dbg-eSzOp0/s.txt: Operation not permitted\n"
  sentinel bytes after: "ORIGINAL\n"

The shell stderr says "Operation not permitted" -- this is the kernel
returning EPERM to the redirect syscall. Exit code 1, sentinel bytes
UNCHANGED. This is REAL defense in depth at the kernel level.

CANCELLATION / DEADLINE CONSERVATION (classification + cleanup)
================================================================

$ cd apps/vscode && bunx vitest run \
    src/sdk/command-job-manager.sandbox-c3-real-kernel.test.ts \
    -t "cancellation"

Tests run:
  PASS: DEFAULT_OFF: deadline fires; terminal state is
        deadline_exceeded                                (3.5s)
  PASS: opt-in seatbelt: deadline fires; same terminal
        classification (no false clean exit; orphan
        absence NOT independently observed)             (3.5s)
  PASS: opt-in seatbelt: profile temp dir is cleaned up
        after deadline (C2-P2 hygiene end-to-end)        (4.0s)

These tests prove:
  - terminal state is `deadline_exceeded` under both DEFAULT_OFF
    and opt-in seatbelt (terminal classification conserved)
  - exitCode is non-zero under both paths (no false clean exit)
  - profile temp dir is cleaned up after deadline (no leak)
  - orphan-descendant absence is NOT directly observed by this
    suite -- it relies on Apple's documented process-inheritance
    semantic (sandboxed child inherits sandbox) plus the
    supervisor's kill tree. See Apple sandbox(7) docs.

PRODUCTION SEAM SANITY (real SBPL profile)
================================================================

$ cd apps/vscode && bunx vitest run \
    src/sdk/command-job-manager.sandbox-c3-real-kernel.test.ts \
    -t "production seam sanity"

Tests run:
  PASS: opt-in seatbelt through production resolver writes a
        real SBPL profile to disk                       (356ms)

Verbatim captured SBPL profile from production seam:

  (version 1)
  (deny default)
  (allow process-exec)
  (allow process-fork)
  (allow signal (target self))
  (allow sysctl-read)
  (allow mach-lookup)
  (allow file-read*)
  (allow file-write*
    (literal "/dev/null")
    (literal "/dev/tty"))
  (deny file-write* (subpath "<workspaceRoot>"))   <- readonlyRoot honored
  (allow file-read-metadata (subpath "/"))
  (deny network*)

The workspace root passed via experimentalSandboxWorkspaceRoots IS
in the profile as a `(deny file-write*)`. The production resolver
threads the workspace root into the capability used by the
production backend. KERNEL-LEVEL PROOF.
