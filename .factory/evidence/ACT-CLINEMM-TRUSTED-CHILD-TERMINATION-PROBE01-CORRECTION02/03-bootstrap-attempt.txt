LaunchAgent-managed instance of the helper. The only way to produce
one is `launchctl bootstrap <domain> <plist-or-binary>`. This section
captures whether that operation can succeed on this substrate.

ROOT PRIVILEGE GATE
-------------------
The bootstrap error message recommends "Try re-running the command as
root for richer errors." Sudo is denied in this Background shell:

Command: sudo -n launchctl bootstrap user/501 com.clinemm.probe.plist
Result:  zsh:2: operation not permitted: sudo
         (sudoers cannot be queried non-interactively in this shell)

`launchctl asuser 501 launchctl bootstrap user/501 <plist>` was also
attempted and returned the same rc=5 "Input/output error" — `asuser`
does NOT elevate privilege to launchd-bootstrap-capable.

CAN THE SUBSTRATE PRODUCE A REAL LAUNCHAGENT HELPER?
----------------------------------------------------
NO. Every variant of the bootstrap operation fails with rc=5 in this
Background shell, and the recovery path (sudo as root for richer
errors) is not available. The substrate cannot bootstrap a real
LaunchAgent-managed helper from this shell.

The PROBE01 ACT's note "launchctl bootstrap into gui/501 was
attempted and failed with Bootstrap failed: 5: Input/output error"
is REPRODUCED here exactly (10-bootstrap-attempt-reproduction.log).
The previous ACT's failure was real, not a transient — it is a
persistent property of this substrate.

CONSEQUENCE FOR THE §5 DISCRIMINATOR
-------------------------------------
Per the reviewer's verdict:
  "If your current development sandbox cannot bootstrap/access the
   real LaunchAgent: CAPTURE_INSUFFICIENT — not
   HALT_HELPER_HAS_NO_SIGNAL_ADVANTAGE."

The substrate cannot produce a real LaunchAgent helper; therefore
the discriminator cannot be honestly run. The correct verdict is
CAPTURE_INSUFFICIENT, not HALT_HELPER_HAS_NO_SIGNAL_ADVANTAGE.

NO BYPASS WAS ATTEMPTED

- No plist was placed in any persistent location.
- The plist's RunAtLoad=false and KeepAlive=false mean it could not
