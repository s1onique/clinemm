## Architectural observation (successor ACT material)

The LIVE contract that an active run blocks commit until
agent_turn_done is currently enforced by the BCB barrier's
checkElmCompletionAuthority consult of lastDecision. The Elm
kernel has a more permissive rule
(completionCommitHoldReasons in Authority.elm:453-460 that filters
ActiveRun when commitReadyRun == activeRun), but it is consulted
ONLY inside handleTaskCompletionCommitted — and
task_completion_committed is excluded from AUTHORITY_STAGES, so
the rule is dead code at the BCB barrier site.

The H1_ELM_TOO_STRICT verdict from
ACT-CLINEMM-COMPLETION-AUTHORITY-ELM-COMMIT-WHILE-RUN-ACTIVE-DISCRIMINATOR01
identified this gap: if/when the LIVE contract is actually expected
to allow commit on submit_and_exit_seen while a run is still active
(the CWRA01 intent), the BCB barrier must be rewired to consult
completionCommitHoldReasons semantics — or task_completion_committed
must be admitted to AUTHORITY_STAGES. Either is a separate, larger
ACT and is OUT OF SCOPE for this ACT. This ACT correctly captures
the current LIVE contract.
