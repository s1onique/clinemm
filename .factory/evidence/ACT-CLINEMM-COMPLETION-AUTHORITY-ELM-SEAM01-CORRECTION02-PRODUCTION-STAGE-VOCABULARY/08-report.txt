GREEN (C1-CORRECTED):
  commitCount = 0 in the SEMANTIC test — NOT 1 as the reviewer's
  first-pass claim suggested.

  Why commitCount = 0 IS the LIVE contract:
    - run_turn_started reaches Elm → activeRun = Just runId
    - submit_and_exit_seen binds commitReadyRun := Just runId (Authority.elm:131)
    - computeHoldReasons returns [ActiveRun] (activeRun /= Nothing)
    - Codec encodes holdReasons = ["ActiveRun"]
    - TS BCB barrier consults lastDecision which reflects the most-recent
      drain (holdReasons = ["ActiveRun"]) → returns "hold"
    - checkElmCompletionAuthority returns false → setTurnPhase("completed", ...)
      is suppressed → commitCount = 0
    - final phase != "completed"

  Why the `commitReadyRun == activeRun` suppression rule (Authority.elm:453-460)
  is NOT consulted at the BCB barrier:
    - The suppression rule lives in completionCommitHoldReasons, consulted
      ONLY inside handleTaskCompletionCommitted (Authority.elm:420).
    - task_completion_committed is deliberately EXCLUDED from AUTHORITY_STAGES
      (it is a POST-DECISION stage; telling the kernel about the decision
      before the decision is a self-fulfilling loop).
    - Therefore handleTaskCompletionCommitted never receives a record in
      normal production flow; completionCommitHoldReasons is dead code
      at the BCB barrier site.
    - The BCB barrier consults lastDecision, which reflects
      computeHoldReasons (unfiltered) — the architecture path.
