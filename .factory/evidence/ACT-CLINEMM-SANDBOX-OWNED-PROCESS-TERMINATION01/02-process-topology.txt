    child.pid == PGID   (POSIX detached: child becomes NEW process group leader)

  CHILD_SID (spawned shell): == CHILD_PID  (newly-created session, due to detached)

Confirmation of process-group identity:
  The supervisor primitive operates on -pgid (= -child.pid since detached).
  process.kill(-childPid, signal) signals EVERY process in the same group.

KEY PRODUCTION OBSERVATIONS:
  - command-job-manager.ts:1154 calls
      job.process.terminateTree({gracefulSignal: "SIGTERM", graceMs: TERM_GRACE_MS})
    with TERM_GRACE_MS = 5000.
  - bash.ts:917 spawn uses detached: true (POSIX) creating a fresh pgid.
  - bash.ts:1029 signalGroup(signal) uses process.kill(-childPid, signal).
  - bash.ts:1094-1101 escalation sends SIGKILL to -pgid after grace expires.
  - bash.ts:1017 probePgidExists treats ESRCH as group-gone, EPERM as still-exists.
  - bash.ts:1141 returns terminateTree in SupervisableShellProcess.

OWNERSHIP IDENTITY (the handle that the cancellation primitive acts on):
  child.pid === PGID (because detached: true on POSIX)

TERMINATION AUTHORITY:
  Host Node process (outside Cline Seatbelt) signals the owned group via
  process.kill(-pgid, signal). Signal delivery reaches the sandboxed child
  at the kernel level; the child's Seatbelt profile (allow signal (target
  self)) does NOT block inbound signal receipt (Seatbelt enforces OUTBOUND
  syscalls from sandboxed processes, not inbound signals from the kernel).

SUBSTRATE OBSERVATION (this host):

  Chromium zygote. The process tree of the entire authoring shell is
  inside that Chromium sandbox. The Cline Seatbelt profile (allow signal
  (target self)) is NOT the cause; the VSCodium sandbox is the cause.
