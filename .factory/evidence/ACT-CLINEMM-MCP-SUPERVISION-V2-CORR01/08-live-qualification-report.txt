WHAT THIS CORRECTION CHANGES ABOUT THE LIVE RUN
------------------------------------------------
The correction does NOT add a new operation. It makes the EXISTING
`clinemm_send_feedback` operation re-enter the SAME lifecycle the
operator's own composer does. The live run therefore gains two
observable expectations:

  * After an accepted feedback, the TaskHeader phase must move to
    `streaming` (Thinking + Cancel) and then to the next terminal
    phase - NOT stay on the stale `completed` / `resumable` phase.
  * A feedback against a `resumable` task must leave the task RUNNING
    (the `same_task_continued` exit), not stuck in `resumable`.

If either is absent in the live run, the lifecycle conservation claim
is broken.
