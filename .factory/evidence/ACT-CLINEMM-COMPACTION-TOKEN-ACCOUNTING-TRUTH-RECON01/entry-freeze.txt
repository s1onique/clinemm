NEW_CAUSAL_CANDIDATE (factory causal reviewer, 2026-09-02 SECOND REORDERING)=
  The post-compaction TaskHeader rescaling (apps/vscode/src/shared/
  getApiMetrics.ts:174-225) crosses two semantic baselines (R0-A):
    - LAST_REQUEST_INPUT (provider-normalized per-request occupancy)
    - WORKING_CONTEXT ESTIMATE shrink ratio (tokensAfter / tokensBefore)
  The displayed header value is their product:
    header = lastRequestInput × (tokensAfter / tokensBefore)
  For the FIRST LIVE symptom (167.1k × 0.04249 ≈ 7.1k), the production
  implementation returns exactly this product. R0-A confirms arithmetic;
  R0-B (the "three permitted quantities" oracle) was HALT_RED_NOT_REPRODUCED
  by the factory causal reviewer on the second reordering and is
  WITHDRAWN. R0-C (doc-comment-vs-behavior) was inconclusive and is
  also WITHDRAWN.

  PIVOT (factory causal reviewer, 2026-09-02 second reordering):
  A NEW LIVE specimen — "Context compacted (manual) · 1M → 72.9k tokens
  · 1234 → 86 messages" with operator intuition that the model was not
  actually carrying ~1M of active context — outranks the previous R0-B
  hypothesis. The upstream denominator (tokensBefore) itself is
  suspicious.

  R0' source-recon (executed 2026-09-02):

    sdk/packages/core/src/runtime/orchestration/session-runtime-orchestrator.ts:1149
      For AUTO compaction, apiMessages = prepareProviderMessagesForApi(messages)
      (goes through messageBuilder.buildForApi — same pipeline as next
      provider-bound request). CONSISTENT.

  CAUSAL FINDING: Manual compaction's `apiMessages = canonical` while
  the next provider-bound request's projection goes through
  `buildForApi`. For manual compaction, `tokensBefore` measures the
  canonical transcript, not the provider-bound working context the UI
  labels. AUTO compaction is consistent.

  The TaskHeader / shared-metrics layer is NOT at fault for this defect;
  it correctly consumes what `tokensBefore` says. The defect lives in
  the two manual entry points. Ownership migrates to SDK entry-point
  normalization (CLI + VSCode compaction bridges).

  R0' deliverable: a real-trace specimen (HOST_REQUIRED) capturing (a)
  manual /compact with known canonical history and (b) the next
  provider-bound request's `buildForApi` output, asserting
  E_before ≈ W_before ≈ P_before on a real run. The current code-trace
  recon is sufficient to NAME the suspect call sites; only a real run
  proves the full three-way equality.

  CASE_B.UI and CASE_B.HYBRID from §7 are RETIRED (R0-B oracle
  unfounded). New branch: CASE_B.MANUAL_PROJECTION.
