## The four conservation guarantees (restated)

The fix is bounded to a single label string. The rest of the state machine
and projection contract is unchanged. Specifically:

1. **Question/approval precedence.** The runtime FSM
   (sdk-session-event-coordinator.ts) never emits awaiting_followup while
   a question or approval is pending. awaiting_approval is its own
   TurnPhase and stateLabel maps it to "Approval" (unchanged). Therefore
   awaiting_followup only fires when no question and no approval is
   pending, and the new label "Your turn" applies to the exact same
   semantic class as the old "Waiting".

2. **Background-work conservation.** stateLabel("streaming") still
   returns { label: "Working", glyph: "●", live: true }. stateLabel
   ("compacting") still returns { label: "Compacting", glyph: "⌄",
   live: true }. Neither phase is relabeled. Active background work is
   visually distinct from "Your turn".

3. **Terminal-state conservation.** stateLabel("completed"), "error",
   "resumable", "idle", "undefined" are all unchanged.

4. **Live clock conservation.** The same-task-continues invariant
   (CORRECTION01) is preserved: live: true on awaiting_followup keeps
   the elapsed clock ticking.

The wire contract is byte-equivalent. The runtime FSM is unchanged. The
only consumer-visible change is the rendered text of the TaskHeader
telemetry strip when the phase is awaiting_followup.
