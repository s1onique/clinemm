ACT-CLINEMM-COMMAND-RISK-V2-MKTEMP-TEMP-AUTHORITY01-CORRECTION03 -- P0-3 RED REPRO

P0-3 was identified by the reviewer in disposition
HALT_MKTEMP_SHELL_RESOLUTION_IDENTITY_UNPROVEN.

Bash's documented command search order (GNU Bash Reference Manual,
Command Search and Execution):

  1. shell function (including exported functions inherited by
     child non-interactive shells via `export -f name`)
  2. shell builtin
  3. $PATH lookup

  Source: https://www.gnu.org/software/bash/manual/html_node/Command-Search-and-Execution.html

The CORRECTION02 evidence used `/usr/bin/which mktemp` which
proves PATH lookup only. The actual executor runs
`bash -c "mktemp"`. Two channels can shadow the proven
identity:

CHANNEL 1: exported shell function (export -f)
  Parent shell:
    mktemp() { printf "BAD %s\n" "${TMPDIR:-/tmp}"; }
    export -f mktemp
  Child non-interactive bash:
    /usr/bin/which mktemp -> /run/current-system/sw/bin/mktemp
                              (or /usr/bin/mktemp depending on PATH)
    type mktemp -> "mktemp is a function"
    bash -c "mktemp" -> function runs, NOT the binary

CHANNEL 2: BASH_ENV startup file
  Non-interactive Bash sources the file pointed to by
  inherited BASH_ENV before executing the command.
  Source: GNU Bash Reference Manual, Bash Startup Files.
  The startup file can define a function named `mktemp`,
  shadowing the binary at lookup time.

OBSERVATION
===========

  Both shadow channels completely bypass the proven
  identity. The CORRECTION02 gate accepts `/usr/bin/mktemp`
  identity (or the GNU realpath on PATH-shadowed hosts),
  promotes to ALLOW, and the executor runs the bash function
  instead of the binary.

SLASH-BYPASS VERIFICATION (the CORRECTION03 fix)
=================================================

Bash Reference Manual, Command Search and Execution:
  "If the command name contains a slash, Bash uses it as a
   pathname and executes it directly, without performing
   function or builtin lookup."

Live verification on this darwin-arm64 host:

  $ bash -c '
  mktemp() { printf "BADFUNC\n"; }
  export -f mktemp
  echo "  bash -c mktemp:"
    bash -c "mktemp"
  echo "  bash -c /usr/bin/mktemp:"
    bash -c "/usr/bin/mktemp"
  '
  Output:
    bash -c mktemp:
    BADFUNC
    bash -c /usr/bin/mktemp:
    /var/folders/0g/mpt_55f524ndzxymkp20wjfc0000gn/T/tmp.36Y4sZK7uc

  $ BASH_ENV=/tmp/clinemm-mktemp-bashenv-... bash -c '
  echo "  bash -c mktemp:"
    bash -c "mktemp"
  echo "  bash -c /usr/bin/mktemp:"
    bash -c "/usr/bin/mktemp"
  '
  Output:
    bash -c mktemp:
    BASHENV_FUNC
    bash -c /usr/bin/mktemp:
    /var/folders/0g/mpt_55f524ndzxymkp20wjfc0000gn/T/tmp.XFxSFBnUG4

The slash-prefixed form BYPASSES both function and BASH_ENV
lookup. The proven identity (realpath of /usr/bin/mktemp) is
the identity that actually executes.

CORRECTION02 IMPLICATION
========================

The CORRECTION02 evidence proved PATH lookup (via
/usr/bin/which mktemp). The actual executor is bash, and
bash's lookup order includes shell functions and BASH_ENV
BEFORE PATH. The proven identity is therefore not bound to
the executed identity for bare `mktemp` and `mktemp -d`.

The leak reproduces for darwin+/usr/bin/mktemp identity+
getconf root on hosts where bash is invoked non-interactively
with `export -f mktemp` or with `BASH_ENV` inherited.

FIX
===

CORRECTION03 restricts the positive AUTO forms to the
explicit-path variants:
  /usr/bin/mktemp        AUTO (slash bypasses lookup)
  /usr/bin/mktemp -d     AUTO

Bare `mktemp` and `mktemp -d` stay ASK with new source
host_mktemp_shell_resolution_unbound documenting the
shell-resolution gap.
