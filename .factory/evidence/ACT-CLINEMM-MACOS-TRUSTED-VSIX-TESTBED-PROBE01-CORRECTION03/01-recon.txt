ACT-CLINEMM-MACOS-TRUSTED-VSIX-TESTBED-PROBE01-CORRECTION03 — recon

Reviewer verdict on CORRECTION02: structural closure on the
transfer seam. Then identified a new P0 with two coupled parts:

1. SSH auth: `BatchMode=yes` requires a non-interactive auth
   mechanism. The Cirrus Sonoma base ships admin/admin; the
   documented mechanism is `sshpass -p admin ssh ...`. The
   current `guestExec()` uses BatchMode=yes with no key path,
   no password, no agent. With the documented default
   credential model this is expected to fail.

2. Editor baseline: the Cirrus `macos-*-base` template installs
   Homebrew + wget/unzip/cmake/gcc/git-lfs/jq/gh/node/ruby —
   not VS Code or VSCodium. The current code's
   `command -v code || command -v codium` finds nothing; the
   testbed would emit `EXTENSION_NOT_FOUND` before any
   ClineMM code ran.

Reviewer-prescribed fix (verbatim):
  "the testbed owns a qualified immutable base, not rely on
  the generic Cirrus `-base` image to coincidentally contain
  what we need."
  Corrected chain:
    Cirrus Sonoma base @ digest
    → one-time testbed image qualification
        - SSH automation method proven
        - exact editor installed
        - editor version recorded
        - ClineMM absent
    → resulting testbed image pinned by digest
    → PROBE01 clones that digest only

Reviewer's discriminator (verbatim):
  Before qualification:
    SSH_AUTH_METHOD       = password_only
    BATCHMODE_CONNECTION  = FAIL
    EDITOR_PRESENT        = false

  After provisioning:
    SSH_AUTH_METHOD       = <sshpass|pinned-key>
    SSH_NONINTERACTIVE    = PASS
    EDITOR_BINARY         = <absolute path>
    EDITOR_VERSION        = <exact version>
    CLINEMM_PREINSTALLED  = false
    BASE_IMAGE_DIGEST     = sha256:...

Reviewer's note on digest staleness:
  "the current Sonoma base digest in your correction evidence
   is already stale relative to the package's currently
   published `latest` digest ... that is another reason the
   qualified testbed image should itself be pinned immutably
   rather than derived ad hoc from `latest` each run."

Reviewer's reopen condition (verbatim):
  "Reopen condition: exact VSIX is transferred as a real byte
  stream/file, host/guest hashes match, then proceed directly
  to the live Tart qualification."

Approach chosen in this ACT:
  - Provision a dedicated SSH public key into the qualified
    image during qualification (not sshpass). Use BatchMode=yes
    + IdentitiesOnly=yes + PreferredAuthentications=publickey
    for the live PROBE01 path. sshpass is used ONCE during
    qualification to bootstrap the key, never per-test-run.
  - Install VS Code (default) at a pinned version during
    qualification. The qualified image bakes the editor
    absolute path and version; the runner pins matching
    constants in runner.ts.
  - The qualified-image digest is captured via `tart list`
    after qualification. PROBE01 clones only that digest.
  - New error codes added: `EDITOR_BASELINE_NOT_PROVEN`,
    `SSH_KEY_NOT_PINNED`. Both fail-closed at the gate in
    runner.ts and inside guest-smoke.ts.
