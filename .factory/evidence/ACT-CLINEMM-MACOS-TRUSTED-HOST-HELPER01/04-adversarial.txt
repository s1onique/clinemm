==================================================================
SEATBELT EXACT-SCOPE (kernel-level)
==================================================================

The ACT §11 requires a kernel-level sibling-deny witness:

  helper.sock        => allowed
  sibling.sock       => denied
  different.sock     => denied

This cannot be reproduced end-to-end in the ClineMM dev sandbox
(sandbox-exec blocked at the kernel; see 02-seatbelt-red.txt).
The structural substitute is the unit test HH-07, which proves
that the SBPL profile text contains ONLY the canonical helper
path-literal — sibling and different socket paths are NOT
present as path-literal grants:

  HELPER      = /Users/me/.clinemm/host-helper.sock
  profile.contains(`(path-literal "${HELPER}")`)      === true
  profile.contains("/Users/me/.clinemm/sibling.sock") === false
  profile.contains("/Users/me/.clinemm/different.sock") === false

The deny-class is structural: any socket that is not the exact
canonical helper path is unreachable because (a) the profile
denies default, (b) the only path-literal network-outbound
grant is for the helper, and (c) the system-socket primitive
is granted for AF_UNIX only, not for any filesystem subpath.

In a substrate-eligible shell (e.g. headed Codium on a
non-sandboxed dev machine), the kernel witness would be:

  /usr/bin/sandbox-exec -f <profile with HH-03 grant> \
    /usr/bin/env node -e 'net.connect("/Users/me/.clinemm/sibling.sock")'
  -> ECONNREFUSED / EPERM (sibling denied)

  /usr/bin/sandbox-exec -f <profile with HH-03 grant> \
    /usr/bin/env node -e 'net.connect("/Users/me/.clinemm/host-helper.sock")'
  -> ok:true (helper allowed)
