CORRECTION_NOTICE:
  A Factory reviewer caught a P0 load-bearing defect in this ACT's
  implementation: the helper's entrypoint (server.ts) did NOT call
  launch_activate_socket(). The plist claimed launchd-owned via Sockets
  dict + launch_activate_socket(), but the entrypoint bound its own
  socket via net.Server.listen({ path }).
  
  The fix is ACT-CLINEMM-MACOS-TRUSTED-HOST-HELPER01-CORRECTION01:
    - helper.c (C, 303 LOC) calls launch_activate_socket("Listener")
      and accepts on the activated fd.
    - Falls back to self-bind when launch_activate_socket returns
      ESRCH (i.e., not under launchd).
    - Plist template updated to point ProgramArguments at the compiled
      C binary.
    - Install script compiles the C helper on `install`.
    - 17 helper.test.ts tests + 3 client.test.ts tests prove the C
      helper works end-to-end on the fallback path.
    - bun:ffi FFI probe proves launch_activate_socket resolves
      against libSystem.B.dylib (returns ESRCH outside launchd).
  
  Status of this parent ACT:
    BEFORE:  PASS (structural substitution glossed over the load-bearing
             claim)
    AFTER:   HALTED -> corrected by CORRECTION01 -> 
             PASS_WITH_LIVE_KERNEL_QUALIFICATION_PENDING
  
  Live launchd activation (under launchctl bootstrap gui/$UID) remains
  substrate-deferred due to the same env constraint (EIO from launchd,
  EPERM from sandbox-exec) that blocked the parent ACT's Seatbelt kernel
  witnesses. The C helper is structurally ready; a substrate-eligible
