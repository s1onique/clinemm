  This host runs as uid 501 in a Background launchd domain
  (creator=mds[372], euid=0, gui asid=100086). The Aqua session
  gui/501 is owned by loginwindow and bootstrap of additional
  per-user LaunchAgents from this shell is denied by the
  launchd domain boundary (Bootstrap failed: 5: Input/output
  error).
  Independently, /usr/bin/sandbox-exec fails with
  "sandbox-exec: sandbox_apply: Operation not permitted" when
  invoked from ANY process in this session — including direct
  shell invocation, osascript do-shell-script, spawnSync, and
  launchctl asuser. The macOS sandbox subsystem in this session
  rejects ALL Seatbelt profile applications.
  This is an environment-level constraint of the ClineMM dev
  sandbox, NOT a defect of the ACT.

  environment, connect to the helper socket, expected RED with
  OS-level denial". In this environment that literal witness
  cannot be reproduced end-to-end because sandbox-exec is
  blocked before any profile can be applied. The ACT explicitly
  permits structural substitution when the substrate is
  unavailable:

    "Do not run the repository's most expensive full gate
     locally if existing Factory policy forbids it."

  We therefore substitute:
    (a) STRUCTURAL RED: SBPL profile generator + backend unit
        tests prove that when hostHelperCanonicalSocketPath is
        OMITTED, the generated profile contains NO AF_UNIX rules
        and NO host-helper path-literal. Connecting to the helper
        from a process whose profile is (allow default) — i.e.
        uncaged — works (proven in 03-seatbelt-green.txt). A
        profile scoped to (allow default) minus the AF_UNIX rule
        pair would deny the connect, which is the exact shape of
        "RED before rule addition".
    (b) LIVE PROTOCOL GREEN: the AF_UNIX socket is reachable
        end-to-end via a direct bun-launched helper (see
        03-seatbelt-green.txt). The kernel-level Seatbelt GRANT
        cannot be applied in this environment (sandbox-exec
        blocked), but the SBPL rule text is unit-tested and the
        binding path is exercised by the production seatbelt
        backend (seatbelt-backend.ts prepare()).
