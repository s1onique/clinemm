try/catch so that ANY failure between successful temp-root synthesis
and the successful return cleans up BOTH the synthesized temp root
AND the profile temp dir before propagating the cause.

==============================================================
WHY caller-supplied tempRoot IS NEVER CLEANED HERE:
==============================================================

In the cleanup() hook returned to the caller, the existing code only
removes `profileDir` and `synthesizedTempRoot` (the dir we allocated).
A caller-supplied `cap.tempRoot` is the caller's responsibility and
MUST NOT be touched by the backend; the caller may have set it to a
path the backend doesn't own (e.g. a workspace-internal scratch dir
that other concurrent commands also use).

The new wrap follows the same rule:
  - bestEffortRm(profileDir)  -- profileDir is always backend-owned
  - bestEffortRm(synthesizedTempRoot)  -- synthesizedTempRoot only
                                         set when we allocated

cap.tempRoot is NOT touched. CORRECTION01 test #2 enforces this.

==============================================================
CLEANUP FAILURE BEHAVIOR:
==============================================================

bestEffortRm swallows errors. A cleanup failure does NOT alter the
propagated cause (the throw statement at the end of the catch is
unconditional). This matches the existing bestEffortRm contract
documented in seatbelt-backend.ts and command-job-manager.ts.

==============================================================
RUNNING-JOB LIFECYCLE:
==============================================================

The cleanup hook is bound to the terminal transition of the supervised
job (NOT to manager.dispose()). Same as before. The wrap does not
change this; it only fixes the case where prepare() fails before
returning.
