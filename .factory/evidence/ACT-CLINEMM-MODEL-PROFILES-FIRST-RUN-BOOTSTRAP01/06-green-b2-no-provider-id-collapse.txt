WHAT WENT GREEN
---------------
The B2 invariant - the strongest invariant in the ACT - is now load-bearing
executable proof. When two ProviderConfigurationInstance records with the
SAME providerId already exist (and the current ApiConfiguration is NOT
bound to either), a bootstrap creates a THIRD instance that matches the
current config exactly. It does NOT pick A or B.

This is the regression guard for the MPWC01 C3 identity-collapse bug.

WITNESS
-------
  MPFRB01_B2_THIRD_INSTANCE: bootstrap creates a THIRD instance that matches
  the current config exactly when two same-providerId instances already exist.

  - Two pre-existing same-providerId instances are seeded (A: endpoint-A.example,
    X-A: 1, physical-key-A; B: endpoint-B.example, X-B: 2, physical-key-B).
  - The CURRENT unbound configuration specifies a THIRD distinct instance (C)
    with modelId=model-C, baseUrl=endpoint-C.example, physical-key-C.
  - The bootstrap primitive is invoked with currentConfig (openai + key C).
  - Result: { status: "CREATED", profileId: ..., instanceId: inst-deterministic-1 }
  - The new instanceId is DISTINCT from A and B.
  - Three instances now exist: inst-A, inst-B, inst-deterministic-1.
  - A and B are UNTOUCHED (no aliasing, no field mutation):
      A: baseUrl=endpoint-A.example, headers={X-A:1}, modelId=model-inst-A
      B: baseUrl=endpoint-B.example, headers={X-B:2}, modelId=model-inst-B
  - The new instance matches the CURRENT config exactly:
      providerId=openai, modelId=model-C, baseUrl=endpoint-C.example
  - The credentialRef resolves to the CURRENT config's credential
    (physical-key-C), NOT to A's or B's credential:
      secretsWritten.get(nameFor(inst-deterministic-1)) === physical-key-C
      secretsWritten.get(nameFor(inst-A)) === undefined  (no cross-write)
      secretsWritten.get(nameFor(inst-B)) === undefined  (no cross-write)

WHY THIS IS THE STRONGEST INVARIANT
-----------------------------------
B2 prevents the bootstrap UX repair from resurrecting the identity-collapse
bug that caused this whole chain. The MPWC01 C3 fix removed the unsafe
`Object.values(instances).find(i => i.providerId === X)` short-circuit in
saveCurrentAsModelProfile. The B2 witness asserts that the new
bootstrapModelProfileFromCurrentConfiguration path does NOT reintroduce
that bug under a different name.

If a future refactor adds any providerId-based shortcut (e.g. "if a
same-providerId instance exists, reuse it"), the B2 witness will fail
because the new instance's modelId will equal A's or B's modelId
(whichever the shortcut returned) instead of the current config's
distinct modelId=model-C.
