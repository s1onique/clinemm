ATOMIC ORDER (frozen — also called out in the ACT body)
-------------------------------------------------------
1. validate current configuration exists
2. validate provider is in V1 support set
3. validate physical credential resolves
4. capture exact connection geometry
5. generate stable opaque instanceId
6. persist physical credential under instance:<instanceId>
   secret namespace
7. persist ProviderConfigurationInstance
8. generate profileId
9. persist ModelProfile referencing instanceId
10. bind current task via writeActiveProfileIdToHistoryItem
11. publish ExtensionState

On failure of any step:
  - the half-created instance/profile must not become visible
    as usable (the caller MUST check the typed result before
    displaying the new profile).
  - secret/instance/profile rows are NOT cleaned up by the
    primitive; the caller decides whether to garbage-collect
    or tolerate unreachable garbage. (Trade-off: cleanup
    complicates the atomicity story and risks cascading
    failure. The fail-closed contract is on the visibility
    surface, not on the underlying storage.)

FAILURE-MODE MAPPING
--------------------
NO_CURRENT_CONFIGURATION
    current config is undefined. User-facing: "No provider
    is configured yet. Set up an API key first in Settings."
CURRENT_CONFIGURATION_UNSUPPORTED
    isSupportedProvider(providerId) returns false. User-facing:
    "Model Profiles does not yet support this provider.
    Only API-key-backed providers are available in V1."
MISSING_CREDENTIAL
    getInstanceSecret resolves to undefined OR the resolved
    secret is empty. User-facing: "This provider is missing
    an API key. Add one in Settings → API Configuration."
INSTANCE_BOOTSTRAP_FAILED
    captureConnection returned undefined OR InstancesStore.write
    threw. User-facing: "Could not capture the current
    configuration. Try again."
PROFILE_WRITE_FAILED
    ProfilesStore.write threw. User-facing: "Profile write
    failed. Try again or check logs."

AMENDMENT NOTE (2026-09-07)
------------------------------------------------------------------------
The reviewer panel flagged three contract issues with this target
signature. The amended freezes (see ACT body §Contract freezes):

  CURRENT_PHYSICAL_CREDENTIAL_SOURCE
    The `resolveCredentialFromCurrentConfig` seam MUST resolve the
    physical API key from the existing current/legacy
    ApiConfiguration / provider-settings authority, NOT from the
    new instance-secret namespace. The amended causal chain is:

        CURRENT/LEGACY CONFIGURATION AUTHORITY
            ↓
        resolve CURRENT physical credential
            ↓
        generate new opaque instanceId
            ↓
        derive instance:<opaque-id> secret name
            ↓
        write physical credential there
            ↓
        persist instance whose credentialRef.name === name
            ↓
        persist profile referencing new instanceId

    NOT: getInstanceSecret(NEW_NAME) ← reads from a namespace that
                                       the operation is creating.

  BOOTSTRAP_COMMIT_MODEL
    The atomic 11-step order is replaced by the two-phase model:
      definition commit  = secret + instance + profile
      post-commit        = task binding + state publication
    Task-binding failure returns CREATED_BINDING_FAILED (truthful
    success-with-warning), NOT a generic failure that hides the
    durable commit. The atomic ordering in this file should be
    read as describing the definition-commit phase only.

  BOOTSTRAP_RPC
    A new dedicated `bootstrapModelProfileFromCurrentConfiguration`
    RPC is added in apps/vscode/proto/cline/state.proto. The
    existing `saveCurrentAsModelProfile` semantics, request type,
    and fail-closed behavior are NOT mutated. The two operations
    have different preconditions and different failure taxonomies;
    they are not two modes of the same RPC.

The frozen failure-mode mapping is also amended:
    CREATED_BINDING_FAILED  — durable commit succeeded, task
                               binding failed; success-with-warning
    (replaces INSTANCE_BOOTSTRAP_FAILED)
The remaining failure reasons stay the same (NO_CURRENT_CONFIGURATION,
CURRENT_CONFIGURATION_UNSUPPORTED, MISSING_CREDENTIAL).
