AUTHORITY BOUNDARY:
  The typed projector at `apps/vscode/src/sdk/instance-store/
  typed-projector.ts:134` (pre-fix) wrote the raw
  `instance.providerId` (= "openai") to
  `CoreSessionConfig.providerId`. The SDK registry at
  `sdk/packages/llms/src/providers/registry.ts:221` keys built-in
  providers by their canonical SDK ids and only knows
  "openai-compatible" (NOT "openai"). The legacy non-profile path
  at `cline-session-factory.ts:1053` calls `toSdkProviderId()`
  before writing `cfg.providerId`; the typed projector path does
  not. The new Model Profile typed projection is therefore
  asymmetric with the working legacy path.

NOT A TWO-STORE BUG:
  The legacy `openai` spelling is NOT introduced by the typed
  instance layer. It is the existing legacy `ApiConfiguration`
  spelling preserved by the bootstrap capture (CORRECTION02
  pinned this behavior — `bootstrap-no-provider-id-collapse.mpfrb01`
  asserts `expect(instC.providerId).toBe("openai")` at line 227).
  The defect is purely at the projection boundary: the typed
  projector is the single seam between the durable typed-instance
  representation and the SDK runtime config, and it lacks the
  legacy-to-canonical alias fold that the legacy
  `buildSessionConfig` path performs at line 1053.

CAUGHT AT THE BOUNDARY:
  The fix point is `apps/vscode/src/sdk/instance-store/
  typed-projector.ts:134` (the call `setOrClear(cfgAny,
  "providerId", instance.providerId)`). Normalizing the input
  through `toSdkProviderId(instance.providerId)` makes the
  projector the SINGLE authority for runtime provider identity,
  matches the legacy non-profile path precedent, and is
  idempotent on already-canonical ids (so existing typed-
  projector test fixtures using "openai-compatible" pass through
  unchanged).
