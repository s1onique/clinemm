Chronology:
  1. host.runTurn({delivery: "queue", prompt: "FINALIZATION_PHASE_1"}) — gate CLOSED, enqueues (C4 fires once)
  2. setReady(true) — open gate

  4. signalRunComplete() — agent.run resolves

  7. Wait for microtasks
  8. Assert dequeue=1, dispatched=1 (phase 1 drained by post-turn drain microtask)
  9. host.runTurn({delivery: "queue", prompt: "FINALIZATION_PHASE_2"}) — second enqueue

  agent ran 3 times (1 user + 2 drains via continue)
  queue empty after drain

VERDICT FOR PPLW-02: GREEN on production code.

The post-turn drain microtask at line 1268 dequeues the queue after the
run ends (phase 1). A subsequent BCB-style enqueue (phase 2) triggers
scheduleDrain which fires when canStartRun()==true (session idle).

Production code handles both ordering directions correctly. The invariant
queue non-empty AND no active run ⇒ drain happens is preserved.

No fix needed for the lost-wakeup hypothesis.
