===============================================================================
Causal-pair / necessity proof via the same backend under different inputs:
===============================================================================

The production builder emits the profile shown above when sandboxOptIn
is enabled. We did not need to construct an ablation pair because:

  A. PASS  (this profile)            -> mktemp exit 0, mktemp -d exit 0
  B. RED   (pre-fix profile)         -> mktemp exit 1, kernel EPERM

The pre-fix profile has no (subpath ...) write grant; the post-fix
profile adds exactly one (subpath "<tempRoot>"). The diff between
profiles IS the necessity ablation: the new grant is necessary and
sufficient for mktemp success.

We did not construct a third "C" profile with the tempRoot grant
but no TMPDIR binding because the design makes it impossible: a
synthesized tempRoot is automatically bound to TMPDIR by the same
single prepare() flow. Splitting the two would require introducing
a new backend option that the contract does not provide.
