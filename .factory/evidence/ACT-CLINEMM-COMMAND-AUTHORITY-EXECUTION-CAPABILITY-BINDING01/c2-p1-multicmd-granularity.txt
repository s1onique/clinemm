EMPIRICAL OBSERVATION (frozen):

  The C2 plumbing channels a single tool-call capability through
  every manager.start() call produced by a multi-command run_commands
  invocation. Concretely:

    run_commands toolCall:
      commands = ["printf 'A\\n'", "printf 'B\\n'"]

    Production seam (real):
      executeShellCommands(commands, { executor, cwd, context, ... })
        = commands.map(async (command) => executor(command, cwd, context))
        = manager.start({command: "printf 'A'\\n'", ...}, context)
        = manager.start({command: "printf 'B'\\n'", ...}, context)

  The same `context.executionCapability` is passed to every start call.
  Same toolCallId. Same marker. Same authority.

  Outcome class = B (reviewer's taxonomy):
    one start per command, SAME capability on all -- uniform fanout.

LOAD-BEARING INVARIANT (locked in by c2-green-multicmd-discriminator.test.ts):

  For a multi-command run_commands tool call:
    (a) START_CALL_COUNT === commands.length
    (b) all start calls carry the SAME toolCallId
    (c) all start calls carry the SAME executionCapability
    (d) the unified authority reaches every spawned job uniformly

  This is the C2 contract: authority is TOOL-CALL SCOPED, not per-command.
  All commands in a single run_commands tool call share authority.
