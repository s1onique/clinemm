  * C: same bounded child lifetime and same post-probe residual check.

       tested Seatbelt instance, and self-exits after 9000 ms. The harness
       verifies the PID by `ps` (exact `foreign.mjs` path + current UID)

       unverified PID. A watchdog only observes; it never signals the
       foreign process. The harness then waits for the foreign fixture to
       exit using a **BOUNDED poll** (150 ticks x 0.1 s = up to 15 s), NOT
       an unbounded `wait` — if the control does not exit inside that
       window the harness aborts with HALT_UNSAFE_FIXTURE. It then
       re-checks `ps` for residual CLINEMM_RECON01_FOREIGN_CONTROL.
       (The bounded-wait pattern was validated in isolation against both a
       fast-exiting child and a 9 s-lifetime child before adoption.)
  * FINAL: a last `ps` sweep for CLINEMM_RECON0* must be empty, else the
       harness aborts with HALT_UNSAFE_FIXTURE.

  The harness NEVER uses pkill, killall, or a process-group sweep. It only
  ever signals a PID it created, and (for probe D) one it has verified by
  `ps` immediately beforehand.
