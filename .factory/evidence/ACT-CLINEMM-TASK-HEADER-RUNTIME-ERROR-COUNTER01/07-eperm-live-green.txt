# Step 1: prove the production bash primitive surfaces EPERM live

Ran from /Volumes/UserData/Users/chistyakov/Projects/SPbNIX/clinemm

$ /Volumes/UserData/Users/chistyakov/.bun/bin/bun \
    /tmp/clinemm-runtime-error-counter-red/red-driver.ts

{"treeTerminated":false,"escalatedToKill":true,"epermDetected":true}

This is the LIVE RED driver from the ACT's red phase (file
`/tmp/clinemm-runtime-error-counter-red/red-driver.ts`). It spawns
`/bin/bash -c "sleep 30"` via `spawnSupervisableShellCommand` (the
exact production primitive CommandJobManager calls), then invokes
`proc.terminateTree({ gracefulSignal: "SIGTERM", graceMs: 50 })`.

The structured result:
  treeTerminated: false   — the tree was NOT reaped cleanly within grace
  escalatedToKill: true   — the manager had to escalate to SIGKILL
  epermDetected: true     — the substrate returned EPERM on kill(-pgid, sig)

This is the EXACT signal that the new ACT surfaces to the task-header
runtime-error counter. Without the ACT, the TaskHeader has no
mechanism to report this fact to the user.
