Causal-review fixes applied to this ACT in place (no new investigation
cycle, no replacement ACT):
  1) hitCount is now NEVER converted into invocation/allocation rate.
     The CPU profile is sample-based; one invocation may receive zero,
     one, or many samples. Allocation capability is established
     structurally via source-code inspection only.
  2) GC adjacency is now computed as TWO clearly labeled metrics:
       PRIMARY      = gc_run_adjacency
                      (one count per contiguous GC run; run-length-
                       independent; 856 = 428 × 2 sanity-checked)
       LEGACY       = gc_sample_weighted_boundary_exposure
                      (per-sample exposure; biased by run length;
                       retained under honest name only)
  3) Method B status is now explicit per target — cwi and e_ are
     TWO_METHOD_AGREEMENT; the rest are METHOD_A_EXACT_BODY_BINDING
     (Method B non-correlatable because the prodlike minified rebuild
     DCE'd/inlined them).
  4) Source HEAD labels are now disambiguated: ANALYSIS_REPO_HEAD
     (= working tree where this analyzer was authored; may differ),
     DOGFOOD_SOURCE_HEAD (= commit that produced the installed dogfood
     bundle, = d92235e67711976eb3582617583e9804034724e3), and
     PROFILE_SUBJECT_HEAD (a .cpuprofile is a captured artifact, not
     a git object, so N/A).
  5) SECOND-ROUND REVIEW FIX (#P0 / aggregation): the PRIMARY and
     LEGACY metric tables are now keyed by leaf `node_id`, not by
     sample index. A second-round review caught that the prior
     `buildTable()` emitted one row per (leafId, GC-run) pair, so
     the same leaf appeared as N duplicate rows. After this fix,
     each `node_id` occurs at most once per leaf_stats table, and
     the analyzer enforces three invariants at build time:
       (I1) sum(rows.before+after) ≤ 2 × gcRuns  (PRIMARY only)
       (I2) every node_id is unique              (PRIMARY and LEGACY)
       (I3) function total == sum of leaf rows   (PRIMARY and LEGACY)
     The analyzer exits with code 3 and refuses to emit
     `result.json` if any invariant fails. Repro of all three is
     trivial (sum the leaf table by `function_name`).

    Rationale for per-round review handling:
      - Round 1: causal mapping was wrong (hitCount == rate; run-
        length multiplication).
      - Round 2: data structure was wrong even though the math was
        right (sampleIdx-keyed rows; function totals a re-aggregation
        the analyzer did not emit).
      - Round 3+: this ACT will not re-open for review unless new
        causation evidence arrives (allocation profile result,
        live qualification, etc.). The bounded successor
        `ACT-CLINEMM-EXTENSION-HOST-ALLOCATION-AUTHORITY01` is the
        next ACT, not a third review cycle of this one.

  6) SECOND-ROUND REVIEW FIX (#P1 / successor primitives): the
     bounded successor ACT's primitive list was changed from
     `v8.writeHeapSnapshot` / `--heap-sampling` / `worker.getHeapSnapshot`
     (two of which are heap snapshots, not allocation sampling) to
     Inspector `HeapProfiler.startSampling` / `stopSampling` with
     `includeObjectsCollectedByMinorGC=true` and
     `includeObjectsCollectedByMajorGC=true`. The minor-GC option
     is load-bearing for this hypothesis (short-lived allocation
     churn dies young; snapshot of survivors would miss it).
     `node --heap-prof --heap-prof-interval=N` is a valid external
     CLI fallback that produces the same shape of profile.
