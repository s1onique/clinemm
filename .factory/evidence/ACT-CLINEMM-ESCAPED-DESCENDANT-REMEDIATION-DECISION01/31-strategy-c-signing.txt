  Result: es_new_client returns 5 = ES_NEW_CLIENT_RESULT_ERR_NOT_ENTITLED.

## Interpretation

  ES_NEW_CLIENT_RESULT_ERR_NOT_ENTITLED = 5 means the kernel rejected
  the new client because the calling binary does NOT hold the
  com.apple.developer.endpoint-security.client entitlement.

  The current helper does not hold that entitlement, so even on a
  runtime/SDK generation exposing es_new_descendants_client()
  (per Apple the symbol is currently Beta; per external
  implementation work it is a macOS 27-era API absent even from the
  macOS 26.x SDK/runtime), the helper could not construct an
  EndpointSecurity client without first being:
    (a) signed by a Developer ID associated with an Apple Developer
        account that has been granted the entitlement, AND
    (b) re-signed with an entitlements blob that contains
        com.apple.developer.endpoint-security.client = true.

  The current build is `linker-signed` (ld -adhoc) with no entitlements
  blob and no Developer ID. Re-signing requires a Developer ID
  certificate chain AND a manually-issued Apple entitlement grant,
  which must be requested from Apple per the
  `com.apple.developer.endpoint-security.client` documentation page.
