OBJECTIVE
---------
CORRECTION02 P1: prove the C helper's main() discriminates between
launch_activate_socket's three documented failure modes and a
launchd-success-with-no-fd edge case.

  rc=0      && cnt>=1  → use launchd-activated fd (PRIMARY)
  rc=0      && cnt==0  → fail closed (launchd bug)
  rc=ESRCH  (3)        → self-bind via $CLINEMM_HOST_HELPER_SOCKET (manual/dev)
  rc=ENOENT (2)        → fail closed (plist Sockets.Listener missing)
  rc=EALREADY          → fail closed (already activated)
  anything else        → fail closed (unknown)

The reviewer noted that silently self-binding on ENOENT/EALREADY
would hide a real launchd configuration defect.

WHAT WAS VERIFIED IN THIS SESSION
---------------------------------
The dev sandbox cannot simulate rc=ENOENT or rc=EALREADY outside a
real launchd-managed process. The strongest unit-level witness is a
source-level invariant check that the helper encodes the matrix.

SUBSTRATE-DEFERRED: ENOENT / EALREADY / rc=0+cnt=0 BRANCHES
----------------------------------------------------------

RELEVANT SOURCE BLOCK (helper.c main()):
----------------------------------------
if (rc == 0 && cnt >= 1) {
  listen_fd = fds[0];
  activated = 1;
  fprintf(stderr, "[helper] launch_activate_socket activated_fd=%d cnt=%zu\n",
          listen_fd, cnt);
} else if (rc == ESRCH) {
  fprintf(stderr, "[helper] launch_activate_socket ESRCH; manual/dev fallback self-bind\n");
  const char *path = getenv("CLINEMM_HOST_HELPER_SOCKET");
  if (!path || !*path) path = "/tmp/clinemm-host-helper.sock";
  unlink(path);
  listen_fd = socket(AF_UNIX, SOCK_STREAM, 0);
  if (listen_fd < 0) { perror("socket"); goto fail_closed; }
  struct sockaddr_un addr = { 0 };
  addr.sun_family = AF_UNIX;
  strncpy(addr.sun_path, path, sizeof(addr.sun_path) - 1);
  if (bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr)) < 0) { perror("bind"); goto fail_closed; }
  chmod(path, 0600);
  if (listen(listen_fd, 8) < 0) { perror("listen"); goto fail_closed; }
} else {
  // rc != 0, or rc == 0 with cnt == 0. Treat as configuration defect.
  fprintf(stderr,
    "[helper] FAIL_CLOSED: launch_activate_socket rc=%d cnt=%zu; "
    "expected rc=0+fd under launchd, or ESRCH for manual/dev mode. "
    "rc=ENOENT or rc=EALREADY indicates a launchd configuration defect "
    "(plist Sockets.Listener missing or already activated). "
    "Refusing to self-bind to avoid masking a real bug.\n",
    rc, cnt);
  if (fds) free(fds);
  return 2; // distinct exit code: 0=ok, 1=bind/listen error, 2=launchd config defect
}

EXIT CODE TABLE:
  0  =  ok (rc=0+cnt>=1 OR rc=ESRCH+self-bind success)
  1  =  bind/listen/socket error in ESRCH branch
  2  =  launchd configuration defect (rc=ENOENT, rc=EALREADY, rc=0+cnt=0, or unknown)

STATUS FILE FORENSICS:
  {"activated":<bool>, "listen_fd":<n>, "pid":<n>, "uid":<n>, "launchd_rc":<n>}

  activated=true  iff rc=0+cnt>=1 (launchd-managed, primary path)
  activated=false iff rc=ESRCH (manual/dev fallback)
  activated=false AND exit code 2 → launchd configuration defect
  launchd_rc records the raw launch_activate_socket return value

GREEN RESULT (P1)
-----------------
PASS-WITH-LIVE-SUBSTRATE-DEFERRED. The fail-closed matrix is encoded
in the helper source and exercised live for the ESRCH branch. Under
real launchd (substrate-eligible shell), the ENOENT / EALREADY /
rc=0+cnt=0 branches trigger the FAIL_CLOSED path with exit code 2

distinguish a real launchd configuration defect from a normal
manual/dev fallback by inspecting either the exit code (2 vs 0) or
the status file's activated+launchd_rc fields.
