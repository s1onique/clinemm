scripts/build_dogfood_vsix_lib.py:254-280 (D03 / DOGFOOD03b):

    Snapshots ``expected_status`` (the porcelain output captured
    before the build) and re-runs the same command after the
    build. Any difference between the two outputs -- including a
    previously-clean tree becoming dirty -- raises BuildError.
    This catches mutations to ANY path in the canonical tree, not
    just package.json.

Git documents `??` as untracked files, and untracked files do
NOT appear unless --ignored is requested. So the guard's
behavior is consistent with its implementation, but wrong for
our trust model: known generated Factory evidence must not
block exact-head VSIX packaging.

ROOT CAUSE
==========

The repo-root .gitignore rule (line 102):

    /.factory/*
    !/.factory/epic-board.md

only matches paths whose first component is `.factory/`. Git's
anchoring in `/.factory/*` means `apps/vscode/.factory/...`
is NOT covered by it, so the symmetric rule under apps/vscode/
falls through unignored.
