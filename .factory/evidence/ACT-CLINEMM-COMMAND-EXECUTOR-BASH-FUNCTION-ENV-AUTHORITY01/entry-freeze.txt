REVIEWER DISPOSITION (BASH-FUNCTION-ENV-AUTHORITY01)
  HALT_AUTHORIZED_BASH_FUNCTION_ENV_UNBOUND

  The earlier "conservation" test for BASH_FUNC_* was
  structurally wrong: shell parameter expansion parses
  `$BASH_FUNC_mktemp%%` as variable `$BASH_FUNC_mktemp`
  followed by literal `%%`, so the test reported non-empty
  without proving that an imported function actually ran.

  Even if the test had been valid, the slash-bypass
  rationale only applies to slash-prefixed commands.
  Bare `pwd`, `git`, `ls`, etc. are still shadowable by
  exported functions in the parent env, because bash
  imports the function from `BASH_FUNC_<name>%%` at
  non-interactive startup and gives it precedence over
  builtin/PATH lookup (per GNU Bash Reference Manual,
  Shell Functions).

  Causal mismatch:
    policy authorized C = "pwd" (general AUTO)
    bash exec: function pwd (imported) > builtin pwd
              > PATH lookup pwd (none of these run)
    imported function executes BEFORE the policy-authorized
    command can

  This is a general executor-boundary defect, not mktemp-
  specific, and is broader than the C2 strip set covered.

SCOPE OF THIS ACT
=================

  Goal: Close the inherited exported-function shadow channel
        for the production Bash executor (under DEFAULT_OFF /
        overlay env semantics).

  Approach: extend the existing strip filter in
            sdk/packages/core/src/extensions/tools/executors/bash.ts
            to also strip any name with the `BASH_FUNC_` prefix
            from the inherited process.env layer BEFORE the
            spread-merge.

  Strip semantics: prefix-match (not enumerable). The function
                  name space is unbounded, so a prefix match is
                  the only safe approach. The matching prefix
                  `BASH_FUNC_` is the documented bash encoding
                  per GNU Bash Reference Manual, Shell Functions.
