RED_PROOF_STYLE = SOURCE_LEVEL (production seam defect isolated
                      by reading the actual code paths)

The defect is reproducible by reading source: there is no path
that publishes the post-compaction W from the manual-compaction
producer seam to the host-side WorkingContextHostCapture carrier.

PRODUCTION_SEAM_RED = REAL

The compactSessionMessages function at apps/vscode/src/sdk/sdk-
compaction.ts:97..156 invokes a ContextPipelinePrepareTurn
(createContextCompactionPrepareTurn) whose return type at
sdk/packages/core/src/extensions/context/compaction.ts:60..111
DECLARES `currentWorkingContextEstimate?: number` as a
published field. The producer DOES compute W (at
publishWorkingContextEstimate at compaction.ts:824..838).

PRODUCTION-SEAM CHAIN (truncated, M-steps only; full chain in
01-production-callgraph.md):

  M4 coordinator.runCompactionInPhase
    -> M5 compactSessionMessages
       -> AWAITS compact({...})
         result = { messages, systemPrompt?, currentWorkingContextEstimate }
       -> RETURNS { compacted, messages, compactionState }   <-- W DROPPED

  M6 result.currentWorkingContextEstimate
    has no recipient anywhere; it is GC'd.

  M7 postStateToWebview reads the carrier verbatim
    (apps/vscode/src/core/controller/state/working-context-state-
     projection.ts:78..84).
    The carrier's _latest is from the LAST prepareTurn for the
    session, never updated by manual compaction.
