WHY THIS FILE EXISTS
--------------------
The review found that the predecessor's GREEN suite exercised ONLY the
request-INITIATION retry authority. Its failure-status matrix was

    [429, 500, 502, 503]

Every entry exercises `maxRetries`. NONE exercises:
  1. the POST-STREAM-START authority (`streamRetries`), and
  2. the EMPTY-RESPONSE authority (`emptyResponseAttempts`).

The review also established an AI SDK subtlety that makes the gap
load-bearing. In the resolved dependency (`ai@7.0.159`):

    "Set to `0` to disable automatic retries while allowing `onError` to
     request one retry. When automatic retries are configured, `onError` can
     request at most one additional retry after they are exhausted. Omit this
     option to disable all stream retry behavior..."

So `streamRetries: 0` disables AUTOMATIC stream retries but STILL permits a
CALLBACK-DIRECTED retry when `onError` returns `{ retry: true }`.

The existing production `onError` (sdk/packages/llms/src/providers/ai-sdk.ts)
is:

    onError: ({ error: streamError }) => {
        const captured = captureStreamError(streamError);
        capturedError.current = captured;
        streamTelemetry.captureError(streamError);
    },

Its arrow function has a BLOCK body and no `return`, so it yields
`undefined` and does NOT request a retry. The effective behaviour is
therefore correct — but it is correct BY ACCIDENT of the callback's return
value, not by construction. This file establishes the behaviour
EMPIRICALLY instead.
