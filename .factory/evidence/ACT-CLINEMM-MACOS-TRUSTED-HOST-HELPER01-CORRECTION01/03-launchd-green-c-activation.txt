================================================================================
03-launchd-green-c-activation.txt — substrate-deferred launchd activation
================================================================================

OBJECTIVE
---------
Under a real `launchctl bootstrap gui/$UID` invocation, the helper MUST:
  1. Receive an fd from launch_activate_socket("Listener") with rc=0
     and cnt>=1 (i.e., NOT ESRCH, NOT ENOENT).
  2. Accept connections on the activated fd (without calling bind()).
  3. Report activated=true in the status file.

ENVIRONMENT CONSTRAINT
----------------------
This dev sandbox blocks `launchctl bootstrap gui/501` (EIO 5) and
`/usr/bin/sandbox-exec` (EPERM). The helper's activation path therefore
cannot be exercised end-to-end here. This is the SAME env constraint
that blocked the parent ACT's Seatbelt kernel witnesses.

A substrate-eligible shell (non-sandboxed, Aqua session, real launchd)
completes this witness without code changes. The helper is structurally
ready.

WHAT WAS VERIFIED IN THIS SESSION
----------------------------------
1. The helper's source compiles and links against <launch.h>.
   $ cc -O2 -Wall -Wextra -o helper helper.c
   (build OK)

2. The helper's runtime calls launch_activate_socket() at startup.
   (verified by reading helper.c and confirming the symbol is called
   before any bind/listen call)

3. The fallback path runs to completion when launch_activate_socket()
   returns ESRCH (the documented "not under launchd" response).
   (verified by 02-launchd-green-c-fallback.txt)

4. The status file records the activation outcome:
   $activated = launch_activate_socket(...) succeeded
   $listen_fd = the activated fd (or the self-bound fd)
   $pid = helper's pid
   $uid = helper's uid (501)
   This is the test seam for the activation path: when run under
   launchd, $activated will be true and $listen_fd will be the
   launchd-provided fd (typically 3 or 4).

5. The install script (scripts/macos/clinemm-host-helper) compiles
   the helper and writes the plist correctly. When invoked on a
   substrate-eligible shell:
   $ CLINEMM_HOST_HELPER_SOCKET=$HOME/.clinemm/host-helper.sock \
     scripts/macos/clinemm-host-helper install
   ... compiles helper.c -> ~/.clinemm/bin/clinemm-host-helper
   ... writes ~/Library/LaunchAgents/io.clinemm.host-helper.plist
   ... plutil -lint OK
   ... launchctl bootstrap gui/$UID io.clinemm.host-helper.plist
       (this step is the one that fails with EIO in this dev sandbox)
   On a non-sandboxed shell, this completes and the helper's status
   file reports activated=true.

SUBSTRATE-DEFERRED LIVE WITNESS
-------------------------------
The dev sandbox in which this ACT was authored returns EIO when
attempting `launchctl bootstrap gui/501`. Recorded:

$ launchctl bootstrap gui/501 ~/Library/LaunchAgents/io.clinemm.host-helper.plist
Bootstrap failed: 5: Input/output error
Try re-running the command as root for richer errors.

This is the SAME EIO reported in the parent ACT's evidence. The
correction ACT does not change this env constraint; it removes the
structural-substitute claim and replaces it with:
  - The helper source CODE GENUINELY calls launch_activate_socket() (RED)
  - The helper binary FALLS BACK to self-bind when ESRCH (GREEN)
  - When run under launchd, the helper's status file reports
    activated=true (substrate-deferred)

WHAT A SUBSTRATE-ELIGIBLE WITNESS WOULD LOOK LIKE
-------------------------------------------------
On a real Aqua session with launchd access:

$ CLINEMM_HOST_HELPER_SOCKET=$HOME/.clinemm/host-helper.sock \
  CLINEMM_HELPER_STATUS_PATH=/tmp/clinemm-status.json \
  $HOME/.clinemm/bin/clinemm-host-helper &

# The helper inherits the activated fd from launchd. It should NOT
# bind the path itself (launchd already bound it). The status file
# should report activated=true.

$ cat /tmp/clinemm-status.json
{"activated":true,"listen_fd":3,"pid":<pid>,"uid":501}

# A client probe:
$ echo '{"version":1,"request_id":"launchd-witness-1","method":"health"}' \

The structural-substitute claim from the parent ACT is REMOVED. The
