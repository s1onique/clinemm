  1. Added `vi.mock("./session-runtime-orchestrator", ...)` at module
     level (same pattern as `runtime-builder.configured-agent-execution.test.ts`).
     The mock captures the `AgentConfig` passed to `new SessionRuntime(config)`.
  2. Added helper `invokeSubAgentAndCaptureChildTools({ config, agentName, prompt })`
     that drives the REAL production child construction path:
        a. DefaultRuntimeBuilder.build({ config: ... })         [production]
        b. Finds `subagent_<name>` in `built.tools`             [production]
        c. Calls `subagent_<name>.execute({ prompt }, ctx)`     [production]
        d. The tool's execute() invokes the production
           `filterToolsForConfiguredAgent(createBuiltinToolsList(...), agent)`
           closure at runtime-builder.ts:594-617.               [production]
        e. The resulting child tools list is passed to
           `createDelegatedAgent({ tools, ... })`               [production]
        f. The mock SessionRuntime captures the config.         [test seam]
        g. Returns `lastCall.tools` as the captured child tool list.
  3. Added 4 NEW tests that exercise the 4 reviewer C1-C4 cases:
        - B4 (reviewer C1): tools: [bash, read_file]
            → child gets [read_files, run_commands] (canonicalized)
        - B5 (reviewer C2-equivalent): skills: [review]
            → child gets [read_files, skills] (skills executor + canonical)
        - B6 (reviewer C3): no tools field
            → child gets full permitted parent/builtin set
        - B7 (reviewer C4): tools: [bash] + toolPolicies.run_commands.enabled=false
            → child gets [] (the two filters compose; empty intersection
              is the correct production behavior).
