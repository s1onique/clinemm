## Production source files verified

apps/vscode/src/sdk/command-job-manager.ts:
  + new public method `releaseForegroundAbortOwnership(jobId)` (line ~2866)
    - O(1) lookup in `this.active`
    - safe no-op when jobId is unknown or job is terminal
    - removes the AbortSignal listener via `removeEventListener`
    - clears `job.abortSignal` and `job.abortListener`
    - DOES NOT touch `job.deadlineTimer`
    - DOES NOT call `terminateTree` / `killTree`

apps/vscode/src/sdk/vscode-run-commands-tool.ts:
  + one new call site at the foreground->background handoff boundary
    (line ~709, inside `if (start.state === "running")` branch)
    - calls `manager.releaseForegroundAbortOwnership(start.jobId)` AFTER
      `start.terminalPromise.then(...)` is attached and BEFORE the
      RUNNING envelope is constructed and returned.
    - idempotent, safe no-op when no caller signal was attached
    - bounded to the background path (the foreground `executeForeground`
      path is unaffected)

## Boundaries observed (one-variable discriminator)

  Production RED vs. GREEN differ only in whether
  `manager.releaseForegroundAbortOwnership(jobId)` is invoked between
  handoff and abort. Everything else (same manager, same supervisor,
  same caller signal, same handoff code path, same command, same wait
  budget) is held constant.

  The bounded ablation therefore establishes the listener retention as
  the necessary cause of the defect.
