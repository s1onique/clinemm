  P0 -- HALT_TEMP_AUTHORITY_SNAPSHOT_IDENTITY:

  CORRECTION04 closed the tampered-paths P0. The fresh-read
  architecture is correctly bounded at cross-instance
  visibility. But the digest exposes a NEW P0 in the
  fresh-read architecture: the temporary-authority set is read
  TWICE during one approval decision (once inside
  buildPathAuthorityEvidence and once before
  getCommandHostAuthorization), with no identity binding
  between the two reads. An external REMOVE between the two
  reads can produce a mixed-generation decision: the evidence
  embeds the OLD authority set while the auth carries the NEW
  one, and the policy re-test authorizes from a snapshot the
  user has already revoked.

  P1 -- CROSS_PLATFORM_ROOT_SHAPE:

  The CORRECTION04 classifier uses literal `path === "/"` for
  filesystem-root detection. On Windows the platform root is
  `C:\` (drive) or `\\server\share` (UNC), not `/`. Granting
  `C:\` would make the entire drive an external authority root.

  P2 -- EOF newline residue:

  path-authority-evidence.ts ended with `}` (no trailing newline).

PURPOSE OF THIS CORRECTION
  Bounded single-axis correction. Three minimal changes:

  1. ONE durable temp-authority read per approval evaluation,
     threaded as one immutable snapshot into both the evidence
     builder and the host authorization.
  2. Cross-platform filesystem-root detection via
     `path.parse(path).root` (handles POSIX `/`, Windows drive
     roots like `C:\`, UNC roots like `\\server\share`, and
     extended-length paths like `\\?\C:\`).
  3. EOF newline cleanup in path-authority-evidence.ts.

  No new persistence mechanism, no watcher, no lock — just
  one fresh-read, one snapshot, one decision.
